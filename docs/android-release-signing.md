# Android release signing preparation

The debug APK is signed with a local debug key and is intended for testing, **not** public distribution. A separately signed Android 1.3.0 APK named `StreetView.apk` is distributed as part of the [published `v2.0.0-alpha.6` GitHub release](https://github.com/markfishurupa-dot/streetview-v2/releases/tag/v2.0.0-alpha.6). Its GitHub-reported SHA-256 matches the independently inspected file (see [verification evidence](apk-v1.3.0-verification.md)). This does not establish which source commit built it or whether an installed older package uses the same signing certificate.

Before distribution, identify the owner of the existing release key and confirm the signing certificate fingerprint of any installed release. Verify package identity and upgrade compatibility on a test device. Decide whether a new key is appropriate for a new distribution or whether the existing key must be retained for updates.

Keep the release keystore, passwords and recovery copies in an access-controlled secret manager outside the checkout and build artifacts. Limit signing access, document key recovery and rotation, and use a protected release environment if automated signing is later approved. Verify the signed artifact and certificate with Android build tools and record checksums and provenance before publication. Never store signing material in Git, issue text, build logs or public CI artifacts.

The owner reports two successful field tests covering six recorded and processed sessions. A device-test report tied to the exact released APK digest and upgrade compatibility with prior signing certificates remain outstanding. The package identifier is currently `com.example.streetview`; changing it affects application identity and requires a separate migration decision.
